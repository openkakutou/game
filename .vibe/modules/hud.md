# Module: hud
**Role:** The in-match HUD: each player's lifebar and power/meter bar, and the round display (round number, each player's round wins, best-of). `hud-renderer.ts` builds the HUD's DOM once (`createHud({ bestOf })`, each bar a `role="progressbar"` with a real `aria-valuemin`/`aria-valuemax` range — never a hardcoded 100 — plus a human-readable `aria-valuetext`/visible value-text span) and mutates it in place on every `update(snapshot)`, never rebuilding. It draws the core's snapshot as it is — `wasm/core-bridge.ts` has already validated it, so there is no HUD-side validation or error state — and only turns health/power into `[0, 100]` bar percentages of `MAX_HEALTH`/`MAX_POWER` (constants mirroring `native/internal/game`'s). A round-number or win-count change fires exactly one `aria-live` announcement; an ordinary health/power-only update never does. Static labels go through this app's `t()`/`onLocaleChange` convention, re-translating in place on a live locale switch without losing the last known values; `dispose()` releases that subscription.
**Files:** `src/hud/hud-renderer.ts`
**Exports:** `MAX_HEALTH`, `MAX_POWER`, `createHud(options): Hud`, `Hud`, `HudOptions`
**Depends on:** `modules/i18n.md` (`t`, `onLocaleChange`), `modules/wasm.md` (`MatchSnapshot`, type only)
