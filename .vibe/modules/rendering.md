# Module: rendering
**Role:** The match scene, once setup is confirmed: composes both fighters' live sprites over the chosen stage's layers, drawn from the state the game core (`modules/wasm.md`'s `core-bridge.ts`) returns each tick for the live player input. `animation-resolution.ts` resolves which `.air` frame is showing at the animation number and elapsed ticks the core reports (walking cumulative per-frame time, holding on a non-positive time, wrapping via `loopStart`). `scene-composition.ts` is pure coordinate mapping/sprite placement/draw-order logic (no DOM/canvas/WASM): stage-space-to-canvas mapping with the core's camera position (fighters move one pixel per camera pixel, a stage layer by its own `deltaX` share), a fighter sprite's axis placed at its live position (facing 1/-1 and frame mirroring resolved as an XOR), stage BG elements ordered behind/in front of the fighters by `layerNo`, and placeholder fallback for any sprite reference that fails to resolve. `sprite-pixel-cache.ts` decodes a given sprite reference at most once per match session (one cache per sheet). `tick-scheduling.ts` is the pure fixed-timestep accumulator math capping how many ticks run per rendered frame. `match-renderer.ts` ties it together: starts the match in the core (the mounted `.def` names of both characters and the stage, the setup — rounds and time limit, 0 meaning none — `p2cpu` when the setup chose a CPU opponent, and the canvas width as the camera's view), resolves the sprites needed for the returned state (cached, batched; item 067 moves that to the core), reads live input once per rendered frame from `modules/input.md`'s `createTickInputSource` and sends that same snapshot with every tick of the frame's catch-up burst, plays the sound cues each tick returns through `modules/audio.md`, and drives the loop — a brief "Preparing match…" status, then `modules/hud.md`'s HUD, a canvas, an `aria-live` announcement, a live input-source status line, `modules/result.md`'s round/match overlay (the loop freezes the instant a tick reports `roundEnded`, the core refusing further ticks until `nextRound`, which the overlay's countdown calls; Rematch calls `renderMatch` again on the same root), and the pause menu (a UI freeze only: Escape or a gamepad's Start stops ticking and the audio). The CPU opponent, the camera, round timing and the round/match outcome are all the core's; a core error replaces the match with a visible message and releases it.
**Files:** `src/rendering/animation-resolution.ts`, `src/rendering/scene-composition.ts`, `src/rendering/sprite-pixel-cache.ts`, `src/rendering/tick-scheduling.ts`, `src/rendering/match-renderer.ts`
**Exports:** `resolveCurrentFrame(frames, loopStart, animTime): Frame`, `findAnimationByNumber(animations, number): Animation | undefined`, `stageXToCanvasX`, `resolveSpriteFlip`, `splitElementsByLayer`, `buildFighterDrawCommand`, `buildStageElementDrawCommand`, `buildMatchDrawPlan(input): DrawCommand[]`, `createSpritePixelCache(): SpritePixelCache`, `computeTicksToRun(accumulatedMs, tickIntervalMs, maxTicksPerFrame): TicksToRun`, `renderMatch(root, input, options?): Promise<MatchRendererHandle>`, `createCanvasSceneDrawer()`
**Depends on:** `modules/wasm.md` (the `character`/`stage` bridges for drawing data, `core-bridge.ts` for the match), `modules/setup.md` (`TimeLimitOption`), `modules/input.md` (`createTickInputSource`), `modules/hud.md` (`createHud`), `modules/result.md` (`createResultOverlay`, `deriveRoundOutcome`/`deriveMatchOutcome`), `modules/audio.md` (`createMatchAudio`, `buildSoundLookup`, `findSound`)
