# Web build generates its roster and stage manifests

## Description
Split from item 028 (2026-11-20), which shipped the native half: the desktop game already discovers `chars/` and `stages/` with no list to edit. The web build still reads hand-written `public/roster-manifest.json` / `public/stage-manifest.json` (committed empty, overwritten per deployment). Decide where the web build's content folder lives, then generate both manifests at build time by scanning `chars/` and `stages/` with the same rules as native (`chars/<name>/<name>.def`, stage `.def` with `[BGdef]`, case-insensitive folder-name order). Waits on 065 so the web roster goes through the core's flow first.

🔒 MUST: real MUGEN 1.0/1.1 and Ikemen GO character/stage folders are discovered as-is, with no file added to them.

## Acceptance Criteria
- [ ] Dropping a character or stage folder into the web content folder makes it appear after a rebuild, with no list to edit
- [ ] The web manifests are generated by the build, never committed by hand
- [ ] Order and discovery rules match the native build
- [ ] A broken content folder still shows the existing clear error state
