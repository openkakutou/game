# Discover characters and stages automatically

## Description
Roadmap decision `029`: no hand-written roster. Today the web roster is a hand-written JSON manifest (`src/roster/manifest.ts`). Native scans the installed `chars/` and `stages/` folders; the web build generates its manifest at build time by scanning the same folders. Display metadata comes only from each content's own files (`.def` `[Info]`, portrait sprite). No sidecar file (roadmap decision `034`): order comes from the screenpack's select screen sort rule (default: folder name, case-insensitive), visibility from the mode's roster filter (default: everything selectable).

🔒 MUST: real MUGEN 1.0/1.1 and Ikemen GO character/stage folders are discovered as-is, with no file added to them.

## Acceptance Criteria
- [ ] Dropping a character or stage folder into the content folders makes it appear, native and web (after rebuild), with no list to edit
- [ ] The web manifest is generated by the build, never committed by hand
- [ ] Discovered content is listed by folder name (case-insensitive) when no sort rule applies
- [ ] A broken content folder still shows the existing clear error state
