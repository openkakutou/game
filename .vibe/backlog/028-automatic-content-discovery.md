# Discover characters and stages automatically

## Description
Roadmap decision `029`: no hand-written roster. Today the web roster is a hand-written JSON manifest (`src/roster/manifest.ts`). Native scans the installed `chars/` and `stages/` folders; the web build generates its manifest at build time by scanning the same folders. Display metadata comes from each content's own files (`.def` `[Info]`, portrait sprite); an optional `openkakutou.json` sidecar in the content folder may override display name, order or hidden state.

🔒 MUST: real MUGEN 1.0/1.1 and Ikemen GO character/stage folders are discovered as-is, with no file added to them.

## Acceptance Criteria
- [ ] Dropping a character or stage folder into the content folders makes it appear, native and web (after rebuild), with no list to edit
- [ ] The web manifest is generated by the build, never committed by hand
- [ ] The sidecar override works and is optional; an invalid sidecar is reported without hiding the content
- [ ] A broken content folder still shows the existing clear error state
