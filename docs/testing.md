# Testing

Run the full suite with `npm test` (Vitest, jsdom environment). Every source file has a co-located `*.test.ts`.

## What each layer's tests cover

- **`src/wasm/bridge.test.ts`** — exercises the *real* `character.wasm` module (downloaded via `npm run wasm:download`, not mocked), injecting Node-backed stubs for the fetch effects so it runs without a server. Covers a valid load (name, animations, sprite metadata, state defs), a malformed `.def`, empty `.sff` bytes, repeated calls reusing the same instantiated module, `resolveSprites` (a real decoded sprite, a sprite the sheet doesn't have, and a batched multi-request call), and (backlog item 013) decoding a real `.snd` file's sound effects when `sndBytes` is supplied (against a real, unmodified fixture also independently pinned by the `snd` library's own tests, not a value derived by this test's own logic), an empty sounds list when `sndBytes` is omitted, and a typed error for a non-empty but invalid `.snd` buffer.
- **`src/wasm/stage-bridge.test.ts`** — the same real-module approach as `bridge.test.ts`, against the real `stage.wasm` (downloaded via `npm run wasm:download:stage`). Covers a valid load (name, stage settings, BG elements, boundaries), a malformed `.def`, an empty `.def` (a valid stage with no `[Info]` section, per the `stage` library's own tolerant parsing), repeated-call reuse, `resolveSprites`, `resolveAnimationFrames` (a resolved frame at a given elapsed-ticks offset, the blank sentinel for a `null` animation, an empty request list), and (backlog item 013) the background music file path when the `.def` declares a `[Music]` section, and an empty path when it declares none.
- **`src/wasm/core-bridge.test.ts`** — the game core bridge against a fake core published through a stub `Go` runtime, so its own loading, envelope parsing and snapshot validation run for real on replies the test controls: `startMatch` sending its request as JSON and returning the id, the HUD values and the first snapshot, the core's reason returned as the error when it refuses, a start reply without an id refused, `tick` sending the id and both players' inputs and returning fighters/timer/wins/cues, an ended round reported with its outcome and winners, every kind of invalid snapshot (a fighter without a numeric field, one fighter only, an unknown outcome, wins not a pair, a missing camera position, a cue naming a side that does not exist, a winner that is not -1/0/1) returned as an error instead of a snapshot, a non-JSON reply and a throwing core call returned as errors, `nextRound`/`closeMatch`, `mountFiles` mounting each name once per page, stopping at the first refusal and retrying a refused name, a failed asset fetch returned as a typed error instead of a rejection, and the module loaded once for any number of calls.
- **`src/wasm/core-bridge.real.test.ts`** — the same bridge against the real `public/wasm/core.wasm` (built by `npm run wasm:core`) with the native build's own test content (`native/testdata/content`) mounted: a match starts with both fighters at their pinned start positions, full health and the HUD values of the setup, ticks count the timer down and an attack hurts the other fighter and returns its sound cue, a round ends at the time limit as a draw with no round winner and a further tick is refused until `nextRound` starts round 2, `p2cpu` makes the core attack a player 1 standing in reach, an unmounted character is refused with the core's reason, and a closed match refuses ticks.
- **`src/roster/manifest.test.ts`** — the manifest fetch/validation logic in isolation: valid entries, an empty roster, invalid JSON, a missing-field entry, a non-array manifest, and a fetch failure.
- **`src/roster/discovery.test.ts`** — the discovery aggregation logic with a fake `loadCharacter`/`fetchBytes`: a successful entry, a character-load failure, a file-fetch failure, an empty roster, and one failing entry resolving independently of a sibling that succeeds.
- **`src/roster/discovery.smoke.test.ts`** — an end-to-end sanity check wiring `discoverRoster` to the real WASM bridge (not fakes) against real fixture bytes, for both a valid and a broken character in the same run.
- **`src/stage/manifest.test.ts`** — the same coverage shape as `roster/manifest.test.ts`, for the stage manifest.
- **`src/stage/discovery.test.ts`** — the same coverage shape as `roster/discovery.test.ts`, for stage discovery.
- **`src/selection/roster-screen.test.ts`** — the selection screen's rendering and interaction: name/portrait display, the empty-roster message, a non-interactive error card, Continue gated on both picks, independent per-player selection, the mirror-match case (both players picking the same character), re-rendering replacing rather than appending content, and (backlog item 009) re-translating the heading/Continue/pick labels, the empty-state message, and an error card's prefix in place on a live locale switch, without losing either player's pick.

## Real-WASM fixtures

`src/wasm/testdata/` holds minimal `.air`/`.sff`/`.cns` fixtures (copied from `character-viewer-web`, which itself copied them from the `character` repo's own test data) used by every test that exercises the real WASM module, so expected values come from actually running the module once against them rather than from the same mapping logic under test. `v1-basic.snd` (backlog item 013) is copied from the `snd` library's own `testdata/files/` — a real, unmodified MUGEN v1 sound file that library's own tests independently pin to group 1 / sample 0, 11025 Hz, 2772 decoded PCM samples, reused here as the same kind of independent ground truth.

## Visual regression tests (backlog item 011)

`npm run test:visual` (Playwright, real headless Chromium, not jsdom) guards the roster and stage selection screens against unintended rendering changes — a category of regression the jsdom suite above can't catch, since jsdom never actually paints anything.

- **`tests/visual/roster-stage.visual.spec.ts`** — three committed screenshot baselines: the roster grid with Player 1's character picked, the roster grid with Player 2's character picked, and the stage grid with a stage selected.
- Served through a dedicated `vite.visual.config.ts` (extends the real `vite.config.ts` via `mergeConfig`) whose `publicDir` points at `tests/visual/fixtures/` instead of the real `public/`, since the roster/stage screens fetch a fixed-URL deploy-time manifest that ships empty in the real, committed `public/`. `npm run prepare-visual-fixtures` copies the downloaded `public/wasm/` build into that fixture tree first. See `.vibe/decisions/008-visual-regression-fixture-serving-strategy.md`.
- Extends `web-ui-kit`'s shared Playwright visual-testing preset (`createVisualProjectConfig`), with a stricter diff threshold (`maxDiffPixelRatio: 0.005` vs. the shared default `0.02`) — confirmed by measurement that a single pick-button color regression sits under the shared default even scoped to one card's own screenshot.
- Runs in CI (`.github/workflows/ci.yml`) on every push to `main` and every pull request: lint, then the visual suite only, uploading the diff as a build artifact on failure. The full `npm test` unit/smoke suite is not run in CI yet — that suite runs in `deploy-pages.yml` before anything is published.

## Real-browser verification

Every layer above is covered by Vitest/jsdom. Both selection screens have additionally been driven in a real headless-Chromium session against the running dev server — jsdom cannot fully substitute for a real browser check on a feature this visual, though no repeatable script for it is checked into this repo yet:
- Backlog item 001 (character roster): roster rendering, independent picks, the mirror-match case, and the Continue confirmation.
- Backlog item 002 (stage selection): stage rendering including a corrupt-stage error card, the radiogroup's single-choice selection, Continue's disabled/enabled states, and the final confirmation naming both players and the chosen stage.
- Backlog item 003 (match setup): both radiogroups' initial/disabled state, Continue staying disabled until both a round count and a time limit are picked, re-selecting the current round count as a no-op, switching the round count without disturbing the time limit pick, and the final confirmation naming both players, the chosen stage, the chosen round count, and the "Unlimited" time limit.
- Backlog item 006 (input handling): the Controls section rendering both players' real default key bindings correctly, the match starting and showing the live "Player 1: Keyboard · Player 2: Keyboard" status, holding a bound key for several seconds with no console errors and no freeze (the canvas keeps updating, the tick loop keeps running).
- Backlog item 009 (localization): a fresh load with the browser's language forced to English shows the roster screen in English with the locale switcher present; picking Player 1's character, then switching the locale switcher to French live-translates the heading/Continue/pick labels with no page reload while the Player 1 pick (and its "✓") is preserved; a persisted French override in `localStorage` wins over an English browser locale on reload.
- Backlog item 013 (match audio): driven against a real headless-Chromium session with a temporary, self-contained fixture roster/stage (a fighter whose `.cns` fires a `PlaySnd` controller every single tick against a real decoded `.snd` fixture, and a stage `[Music]` file pointing at deliberately undecodable bytes) served through the plain dev server — confirmed for real: a full match runs end-to-end (character/stage selection, setup, live rendering) with the `PlaySnd` controller firing on every tick of a multi-second run and no console/page error at any point; the undecodable stage music degrades to silence with no thrown error; and a simulated tab-visibility change (hidden, then visible again) mid-match produces no crash or error. The native (SDL2_mixer) half was delivered later as backlog item 020, see `.vibe/decisions/016` and the "Native audio tests" section below.
- Backlog item 007 (round/match result, CPU opponent): driven against the real `engine`/`character`/`stage` WASM modules through the visual-fixture serving path (`vite.visual.config.ts`), with zero console/page errors observed. Confirmed for real: the Player 2 Control section defaults to Human and toggling to CPU swaps the Controls section to a "controlled automatically" note; a match starts with CPU enabled and the render loop runs continuously (900+ real simulation ticks observed) with the CPU-aware input wrapper active every frame, without any error or freeze. Two pre-existing, out-of-scope limitations were found while attempting to observe a live round ending, and are noted here rather than worked around: (1) `engine`'s `Tick()` never decrements `MatchState.RoundTimer` (confirmed by reading `engine`'s own source — only `match.NewMatchState` ever sets it), so a timeout-based round ending cannot currently happen in a real match at all, only a KO/double-KO can; (2) the visual-regression fixture character's `.cns`/`.cmd` files (authored for parsing tests, not gameplay) define no command that resolves to a working `HitDef` trigger and no velocity response to held movement input, so neither a human nor the CPU opponent can land a hit or visibly move using that fixture. Both are `engine`-repo/fixture-data gaps, not defects in this item's own code — the round/match-end mechanics themselves (mid-burst cutoff, `resetRound`, rematch, back-to-select) are instead verified via the mutation-tested `match-renderer.test.ts` suite above and the real-WASM `resetRound` round-trip in `wasm/engine-bridge.test.ts`.

## Native audio tests

The native program (`native/`) is tested in Docker with `native/scripts/test.sh` (gofmt, `go vet`, `go test ./...`) and exercised for real by `native/scripts/smoke.sh`. Both run with `SDL_AUDIODRIVER=dummy`, so they prove the mixer opens, music loads and effects reach it, not what is audible.

- **`native/internal/game/audio_test.go`** (no cgo) — the sound-cue queue (cues drained once, in side order; reset on a new round; a real `Match.Step` on the attack state queues the fixture fighter's `PlaySnd`), `FindSound` (hit, unknown key, empty PCM, undecodable sound, character without sounds), the in-memory WAV header (pinned byte for byte) and which match owns the stage music on each screen (match, next round, result, back to select, rematch, error).
- **`native/internal/audio/audio_test.go`** (cgo, dummy driver) — the mixer opening with 44.1 kHz stereo and 16 channels, a silent player when it cannot open, the music starting, continuing across rounds and the result screen, stopping on back to select and restarting on rematch, missing or corrupt music leaving silence with one warning, a known sample playing on one channel, effects beyond 16 channels dropped silently, unknown or undecodable samples skipped with one warning, an owner change silencing effects and emptying the sample cache, a rematch with another sample bank playing the new sample, no allocation on an idle frame, and `Close` being idempotent.
- **`native/scripts/smoke-inner.sh`** — the real binary under Xvfb: the log must show the dummy audio driver, no audio warning, and the engine's `PlaySnd` reaching the player.

Test audio fixtures (`native/testdata/content/stages/arena.wav`) and how to regenerate them: `native/testdata/README.md`.
